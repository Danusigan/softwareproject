# Hosting & auto-deploy (AWS + GitHub Actions)

Every push to `main` is tested, built into Docker images, pushed to Docker Hub and deployed to
AWS automatically.

```
git push ─► GitHub Actions (.github/workflows/ci-cd.yml)
              1. backend tests (MySQL service container) + frontend tests
              2. docker build ─► Docker Hub  danusigan/lopo-{backend,frontend}:<commit-sha>
              3. AWS login (OIDC) ─► open SSH for this runner only ─► ansible-playbook deploy.yml ─► close SSH
                                                                         │
App server (EC2, t3.small): nginx :80 ─► Spring Boot :8080 ─TLS─► Amazon RDS MySQL 8.0 (private)
```

| Tool | Job | Files |
|---|---|---|
| Terraform | Creates VPC, EC2 app server, RDS, security groups, fixed IP, GitHub deploy role | `infra/terraform/` |
| Ansible | Installs/configures the server; performs each deploy | `infra/ansible/` |
| GitHub Actions | Tests, builds, pushes and deploys on every push to `main` | `.github/workflows/ci-cd.yml` |
| Docker Hub | Stores images, one tag per commit | `danusigan/lopo-backend`, `danusigan/lopo-frontend` |
| RDS | The production database, with automatic backups | `infra/terraform/rds.tf` |

**Where secrets live:** DB passwords and the JWT secret are generated by Terraform. They exist
only in the encrypted S3 state bucket and in `/opt/lopo/.env` (mode 600) on the app server. Mail
settings are in the Ansible vault (`infra/ansible/vars/vault.yml`, encrypted). GitHub holds only
the Docker Hub token and a deploy-only SSH key. There are **no AWS keys in GitHub**: the deploy
job logs in via OIDC to a role that can do nothing except add or remove SSH rules on the app
server's firewall. None of these secrets are in git.

**SSH exposure:** port 22 on the app server is open only to `admin_cidrs` (your IP). During a
deploy, the workflow adds a temporary rule for its own runner IP and removes it at the end, even
if the deploy fails.

**Approximate cost (ap-south-1):** app t3.small ~$16, RDS db.t4g.micro + 20 GB ~$15, public IP ~$4
per month. GitHub Actions minutes are free for this usage. On an AWS Free plan account this comes
out of the free credits.

## One-time setup

### 0. Tools (Windows → use WSL)

Terraform, Ansible and the AWS CLI run in WSL (Ubuntu). **Clone the repo inside WSL** (e.g.
`~/softwareproject`), not under `/mnt/d/...`. Files on the Windows drive look world-writable to
Linux, so Ansible ignores `ansible.cfg` there and SSH refuses keys stored there.

```bash
sudo apt-get install -y ansible            # Terraform + AWS CLI: see hashicorp.com / aws docs
git clone https://github.com/Danusigan/softwareproject.git ~/softwareproject
```

### 1. Accounts & keys

1. **AWS**: an IAM user with `AdministratorAccess` and an access key, then `aws configure`
   (region `ap-south-1`). Check with `aws sts get-caller-identity`.
2. **SSH keys**: one for you (admin), one only for GitHub Actions deploys:
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/lopo_deploy -N ""
   ssh-keygen -t ed25519 -f ~/.ssh/lopo_gha -N "" -C github-actions-deploy
   ```
3. **Docker Hub**: Account settings → Personal access tokens → *Generate* with **Read & Write**.
   The repositories `lopo-backend` and `lopo-frontend` are created automatically (public) on the
   first push. Images contain no secrets; those are injected only at runtime.

### 2. Terraform: create the infrastructure

```bash
# a) State bucket (once per AWS account)
cd ~/softwareproject/infra/terraform/bootstrap
terraform init && terraform apply           # note the printed state_bucket

# b) Main stack
cd ..
cp backend.hcl.example backend.hcl          # put the bucket name in
cp terraform.tfvars.example terraform.tfvars
curl -s https://checkip.amazonaws.com       # put <that IP>/32 into admin_cidrs
terraform init -backend-config=backend.hcl
terraform apply                             # ~10-15 min (RDS is the slow part)
```

On an AWS **Free plan** account, also set `db_backup_retention_days = 1` in `terraform.tfvars`
(the Free plan rejects longer backup retention).

The outputs include `app_url` and `github_actions_variables`. Terraform also writes
`infra/ansible/inventory/hosts.ini`.

### 3. (Optional) Mail settings for password-reset emails

```bash
cd ~/softwareproject/infra/ansible
cp vars/vault.yml.example vars/vault.yml    # fill in the Gmail address + App Password
ansible-vault encrypt vars/vault.yml        # choose a vault password and store it safely
```

Skip this and the app still works; only "forgot password" emails fail.

### 4. Ansible: configure the server

```bash
cd ~/softwareproject/infra/ansible
ssh-keyscan -H <app_public_ip> >> ~/.ssh/known_hosts
ansible all -m ping                         # expect "pong" from app-server
ansible-playbook site.yml                   # add --ask-vault-pass if you did step 3
```

This installs Docker, authorizes the GitHub Actions deploy key (`~/.ssh/lopo_gha.pub`), creates the
least-privilege DB user on RDS and writes the app's `.env`. Re-run it any time you change server
config or mail settings. It is safe to repeat.

### 5. GitHub: secrets and variables

Repository → **Settings → Secrets and variables → Actions**.

**Secrets** tab → *New repository secret*:

| Name | Value |
|---|---|
| `DOCKERHUB_USERNAME` | `danusigan` |
| `DOCKERHUB_TOKEN` | the Docker Hub access token |
| `APP_SSH_KEY` | the whole output of `cat ~/.ssh/lopo_gha` (private key, including the BEGIN/END lines) |

The backend test job also needs `DB_USERNAME`, `DB_PASSWORD` and `DB_NAME`. These are for the
throwaway test MySQL only, not production; any values work.

**Variables** tab → *New repository variable*:

| Name | Value |
|---|---|
| `AWS_DEPLOY_ROLE_ARN` | from `terraform output github_actions_variables` |
| `APP_SG_ID` | from `terraform output github_actions_variables` |
| `APP_HOST` | from `terraform output github_actions_variables` |
| `APP_SSH_HOST_KEY` | output of `ssh-keyscan -t ed25519 <APP_HOST> 2>/dev/null` (one line) |

### 6. First deploy + first login

Push to `main` (or re-run the latest workflow in the **Actions** tab). When the `Deploy to AWS`
job is green, open `app_url`.

A fresh database has no users, so create the first Superadmin once:

```bash
cd ~/softwareproject/infra/ansible
ansible-playbook create-superadmin.yml      # prompts for username, email, password
```

Log in with it; admins and lecturers are then created from inside the app. Program Outcomes are
not auto-created either: as admin, use **Initialize Defaults** for the Washington Accord PO1–PO12.

## Day-to-day

| Task | How |
|---|---|
| Deploy | `git push` to `main`. Nothing else. |
| See why a deploy failed | GitHub → **Actions** → the red run → the failed job's log |
| Roll back | `cd infra/ansible && ansible-playbook -l app deploy.yml -e image_tag=<older-commit-sha>` (full SHA; Docker Hub has every commit's image) |
| App logs | `ssh -i ~/.ssh/lopo_deploy ubuntu@<app-ip>` then `docker logs -f softwareproject-backend` |
| Your IP changed (SSH times out) | Update `admin_cidrs` in `terraform.tfvars`, `terraform apply` |
| Change mail settings | `ansible-vault edit vars/vault.yml` then `ansible-playbook site.yml --ask-vault-pass` |
| Restore the DB | AWS console → RDS → `lopo-mysql` → *Actions → Restore to point in time* (within the backup retention window). This creates a **new** instance; point `DB_HOST` at it or rename it. |
| Manual DB snapshot (before risky changes) | RDS → `lopo-mysql` → *Actions → Take snapshot* |
| Rotate DB/JWT secrets | `terraform apply -replace=random_password.db_app` (or `jwt_secret`) then `ansible-playbook site.yml`. Rotating the JWT secret logs everyone out. |

### Moving existing data into RDS (optional, once)

If real data already exists in another MySQL:

```bash
# where the data is
mysqldump --single-transaction --no-create-info --skip-triggers \
  --ignore-table=<db>.flyway_schema_history -u <user> -p <db> > data.sql
scp -i ~/.ssh/lopo_deploy data.sql ubuntu@<app-ip>:~
# on the app server (RDS is only reachable from there). Flyway has already created the tables.
MYSQL_PWD=<db_master_password> mysql --ssl-mode=REQUIRED -h <db_host> -u lopo_admin obqa < data.sql
```

`terraform output -raw db_master_password` and `terraform output db_host` give the values.

### HTTPS (when there is a domain)

Point the domain's A record at the app IP, then add TLS (e.g. certbot/Caddy in front of the
frontend container). Update `vault_app_frontend_url` to `https://...` and re-run `site.yml`.

### Tearing down

```bash
cd ~/softwareproject/infra/terraform
terraform destroy
```

If `db_deletion_protection` is still `true`, set it to `false` and `terraform apply` first. A final
snapshot `lopo-mysql-final` is kept; delete it in RDS → Snapshots if you don't need the data.
The state bucket from `bootstrap/` is protected against deletion; empty and delete it in the S3
console last.
