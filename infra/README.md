# Hosting & auto-deploy (AWS + Jenkins)

Every push to `main` is tested, built into Docker images, pushed to Docker Hub and deployed to
AWS automatically.

```
git push ─► GitHub webhook ─► Jenkins (EC2, t3.medium)
                                 1. backend tests (throwaway MySQL container) + frontend tests
                                 2. docker build ─► Docker Hub  danusigan/lopo-{backend,frontend}:<commit-sha>
                                 3. ansible-playbook deploy.yml ─► App server
                                                                    │
App server (EC2, t3.small): nginx :80 ─► Spring Boot :8080 ─TLS─► Amazon RDS MySQL 8.0 (private)
```

| Tool | Job | Files |
|---|---|---|
| Terraform | Creates VPC, 2 EC2 servers, RDS, security groups, fixed IPs | `infra/terraform/` |
| Ansible | Installs/configures servers; performs each deploy | `infra/ansible/` |
| Jenkins | Runs the pipeline on every push | `Jenkinsfile` |
| Docker Hub | Stores images, one tag per commit | `danusigan/lopo-backend`, `danusigan/lopo-frontend` |
| RDS | The production database, with daily backups | `infra/terraform/rds.tf` |

**Where secrets live:** the DB passwords and JWT secret are generated by Terraform and exist only in
the encrypted S3 state bucket and in `/opt/lopo/.env` (mode 600) on the app server. Mail settings are
in the Ansible vault (`infra/ansible/vars/vault.yml`, encrypted). The only secret stored in Jenkins
is the Docker Hub token. None are in git.

**Approximate cost (ap-south-1, on-demand):** about US$70–80/month in total. Roughly: Jenkins
t3.medium ~$33, app t3.small ~$16, RDS db.t4g.micro + 20 GB ~$15, 2 public IPs ~$7. New AWS
accounts may have free-tier credit. Check the AWS Pricing Calculator for exact current figures.

## One-time setup

### 0. Tools (Windows → use WSL)

Terraform and Ansible run from Linux. On Windows, install WSL once (PowerShell as admin):

```powershell
wsl --install -d Ubuntu
```

Then, **inside the Ubuntu terminal**:

```bash
# Terraform
sudo apt-get update && sudo apt-get install -y gnupg software-properties-common curl unzip
curl -fsSL https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp.gpg
echo "deb [signed-by=/usr/share/keyrings/hashicorp.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" \
  | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt-get update && sudo apt-get install -y terraform ansible

# AWS CLI v2
curl -s "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip
unzip -q awscliv2.zip && sudo ./aws/install && rm -rf aws awscliv2.zip
```

> **Clone the repo inside WSL** (e.g. `~/softwareproject`), not under `/mnt/d/...`. Files on the
> Windows drive look world-writable to Linux, so Ansible ignores `ansible.cfg` there and SSH refuses
> keys stored there.

```bash
git clone https://github.com/Danusigan/softwareproject.git ~/softwareproject
```

### 1. Accounts & keys

1. **AWS**: in the AWS console → IAM → create a user with `AdministratorAccess` → Security
   credentials → *Create access key* (CLI). Then:
   ```bash
   aws configure        # paste the key + secret, region: ap-south-1, output: json
   ```
2. **SSH key** that Terraform installs on both servers:
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/lopo_deploy -N ""
   ```
3. **Docker Hub**: Account settings → Personal access tokens → *Generate* with **Read & Write**. Keep it
   for step 5. The repositories `lopo-backend` and `lopo-frontend` are created automatically (public)
   on the first push. Public images are fine: they contain no secrets, which are only injected at
   runtime.

### 2. Terraform: create the infrastructure

```bash
# a) State bucket (once per AWS account)
cd ~/softwareproject/infra/terraform/bootstrap
terraform init && terraform apply           # note the printed state_bucket

# b) Main stack
cd ..
cp backend.hcl.example backend.hcl          # put the bucket name in
cp terraform.tfvars.example terraform.tfvars
curl -s https://checkip.amazonaws.com       # put <that IP>/32 into admin_cidrs
terraform init -backend-config=backend.hcl
terraform apply                             # ~10-15 min (RDS is the slow part)
```

The outputs show `jenkins_url` and `app_url`. Terraform also writes `infra/ansible/inventory/hosts.ini`.

### 3. (Optional) Mail settings for password-reset emails

```bash
cd ~/softwareproject/infra/ansible
cp vars/vault.yml.example vars/vault.yml    # fill in the Gmail address + App Password
ansible-vault encrypt vars/vault.yml        # choose a vault password and store it safely
```

Skip this and the app still works; only "forgot password" emails fail.

### 4. Ansible: configure both servers

```bash
cd ~/softwareproject/infra/ansible
ansible-playbook site.yml                   # add --ask-vault-pass if you did step 3
```

This installs Docker on both servers, and Jenkins (with Ansible) on the Jenkins server. It sets up
the Jenkins → app-server deploy SSH key and creates the least-privilege DB user on RDS. It also
writes the app's `.env`. At the end it prints the **Jenkins initial admin password**.

Re-run `site.yml` any time you change server config or mail settings. It is safe to repeat.

### 5. Jenkins (browser, once)

1. Open `jenkins_url`, paste the initial admin password → **Install suggested plugins** → create
   your admin user → keep the suggested Jenkins URL.
2. **Manage Jenkins → Credentials → System → Global → Add credentials**
   - Kind: *Username with password*, ID: **`dockerhub`**, username `danusigan`, password: the Docker
     Hub access token.
   - If the GitHub repo is **private**, add another one: *Username with password*, ID `github`,
     password: a GitHub fine-grained token with *Contents: read-only*.
3. **New Item** → name `lopo` → **Pipeline** → OK:
   - *Triggers*: tick **GitHub hook trigger for GITScm polling**
   - *Pipeline*: Definition **Pipeline script from SCM**, SCM **Git**, Repository URL
     `https://github.com/Danusigan/softwareproject.git` (plus the `github` credential if private),
     Branch `*/main`, Script Path `Jenkinsfile` → Save.

### 6. GitHub webhook

Repository → **Settings → Webhooks → Add webhook**
- Payload URL: `http://<jenkins-ip>:8080/github-webhook/` (the trailing slash matters)
- Content type: `application/json`, event: *Just the push event* → Add.

### 7. First deploy + first login

Click **Build Now** on the `lopo` job (or push a commit). When it's green, open `app_url`.

A fresh database has no users, so create the first Superadmin once:

```bash
cd ~/softwareproject/infra/ansible
ansible-playbook create-superadmin.yml      # prompts for username, email, password
```

Log in with it; admins and lecturers are then created from inside the app. Program Outcomes are
not auto-created either: as admin, use **Initialize Defaults** for the Washington Accord PO1–PO12.

## Day-to-day

| Task | How |
|---|---|
| Deploy | `git push` to `main`. Nothing else. |
| See why a deploy failed | Jenkins → `lopo` job → the red build → *Console Output* |
| Roll back | `cd infra/ansible && ansible-playbook -l app deploy.yml -e image_tag=<older-commit-sha>` (Docker Hub has every commit's image; the SHA is the first 12 chars shown in Jenkins) |
| App logs | `ssh -i ~/.ssh/lopo_deploy ubuntu@<app-ip>` then `docker logs -f softwareproject-backend` |
| Change mail settings | `ansible-vault edit vars/vault.yml` then `ansible-playbook site.yml --ask-vault-pass` |
| Restore the DB | AWS console → RDS → `lopo-mysql` → *Actions → Restore to point in time* (any second in the last 7 days). This creates a **new** instance; point `DB_HOST` at it or rename it. |
| Manual DB snapshot (before risky changes) | RDS → `lopo-mysql` → *Actions → Take snapshot* |
| Rotate DB/JWT secrets | `terraform apply -replace=random_password.db_app` (or `jwt_secret`) then `ansible-playbook site.yml`. Rotating the JWT secret logs everyone out. |

### Moving existing data into RDS (optional, once)

If real data already exists in another MySQL (e.g. the old server):

```bash
# on the old server
mysqldump --single-transaction --no-create-info --skip-triggers \
  --ignore-table=<db>.flyway_schema_history -u <user> -p <db> > data.sql
scp data.sql ubuntu@<app-ip>:~
# on the app server (RDS is only reachable from there). Flyway has already created the tables.
MYSQL_PWD=<db_master_password> mysql --ssl-mode=REQUIRED -h <db_host> -u lopo_admin obqa < data.sql
```

`terraform output -raw db_master_password` and `terraform output db_host` give the values.

### HTTPS (when there is a domain)

Point the domain's A record at the app IP, then add TLS (e.g. certbot/Caddy in front of the
frontend container). Update `vault_app_frontend_url` to `https://...` and re-run `site.yml`.

### Tearing down

`terraform destroy` removes everything **except** the database: `deletion_protection` is on.
To really delete it, set `db_deletion_protection = false` in `terraform.tfvars`, `terraform apply`,
then destroy. A final snapshot `lopo-mysql-final` is still kept.
