# 04 — Security Requirements

Requirements are derived from OWASP ASVS (Level 1/2, scoped to what applies to this stack) and mapped to OWASP Top 10 (2021) categories. "Current status" reflects the confirmed state of the code as of this Phase 1 review; "Verification method" is how each will be checked once implemented (Phase 5/6) and later tested (Phase 7+).

| ID | OWASP category | Requirement | Current status | Verification method |
|---|---|---|---|---|
| REQ-AC-01 | A01: Broken Access Control | Every endpoint must enforce role-based authorization server-side (not just `.authenticated()`). | **FAILS** — no `@PreAuthorize`/role check found in any of the 15 REST controllers (`SecurityConfig.java`). | Attempt cross-role calls with a Lecturer JWT against Admin-only endpoints; expect 403. |
| REQ-AC-02 | A01: Broken Access Control | A Lecturer must only access/modify data for modules they own (object-level authorization, not just role-level). | **FAILS** — no ownership check found in `OBEController`/module endpoints. | Attempt Lecturer A accessing Lecturer B's module data via ID manipulation (IDOR test). |

| REQ-LOG-01 | A09: Security Logging & Monitoring Failures | Authentication events and privileged actions (mapping approval, marks edits) must be logged with actor + timestamp. | **FAILS** — no audit log exists anywhere in the system. | Confirm audit records are created for login, mapping approval, and marks edit actions. |
| REQ-DEP-01 | A06: Vulnerable & Outdated Components | Dependencies must be scanned for known CVEs on a recurring basis. | Partial — CodeQL runs in CI; no dependency-check (`mvn dependency-check`, `npm audit`) currently run. | Run `mvn dependency-check:check` and `npm audit`; review CI CodeQL output. |
| REQ-STORAGE-01 | A05 (client-side) | JWT client-side storage mechanism must match the app's actual XSS risk tolerance (httpOnly cookie vs `localStorage`, with tradeoffs documented). | Currently `localStorage`, no documented rationale. | Decision documented in Phase 4; if changed, confirm token no longer readable via `document.cookie`/JS. |

## Non-functional requirements

- CORS locked to real deployed origins before any non-local rollout.
- CSRF stance (currently disabled, appropriate for stateless JWT with no cookie-based session) must be explicitly justified in Phase 4 rather than left as an unexamined default.
- Rate limiting specifically on `/api/auth/login`, tuned to not block legitimate lecturer/admin usage during peak reporting periods.
- Backup strategy for the MySQL data volume must exist and be documented, even if simple, given `ddl-auto=update` is currently unguarded.

## How this feeds later phases

Every "FAILS" row here becomes a concrete Phase 5 implementation task; every "Passes so far" row becomes a Phase 6 re-confirmation task (verify it wasn't broken by other changes).
